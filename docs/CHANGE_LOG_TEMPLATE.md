# 變更記錄模板

使用此模板記錄每次代碼或文檔的變更。

## 變更記錄格式

```markdown
## [日期] - YYYY-MM-DD

### 變更類型
- [ ] 新功能 (feat)
- [ ] 錯誤修復 (fix)
- [ ] 文檔更新 (docs)
- [ ] 代碼格式調整 (style)
- [ ] 代碼重構 (refactor)
- [ ] 測試相關 (test)
- [ ] 建置過程或輔助工具的變動 (chore)

### 變更描述
簡要描述本次變更的內容和目的。

### 變更檔案
列出所有變更的檔案：
- `檔案路徑1` - 變更說明
- `檔案路徑2` - 變更說明

### 影響範圍
- [ ] 前端功能
- [ ] 後端功能
- [ ] 文檔
- [ ] 配置
- [ ] 測試
- [ ] 部署

### 測試說明
描述如何測試本次變更。

### 相關 Issue/PR
- Issue #XXX
- PR #XXX

### 備註
其他需要說明的內容。
```

## 使用範例

```markdown
## [2025-01-20] - 2025-01-20

### 變更類型
- [x] 文檔更新 (docs)
- [x] 建置過程或輔助工具的變動 (chore)

### 變更描述
整理專案檔案結構，創建完整的技術架構文檔，合併重複的安全文檔。

### 變更檔案
- `docs/ARCHITECTURE.md` - 新增技術架構文檔
- `docs/SECURITY.md` - 合併 SECURITY_README.md 內容
- `docs/SECURITY_README.md` - 已刪除，內容合併至 SECURITY.md
- `docs/CHANGELOG.md` - 更新變更記錄
- `README.md` - 更新文檔引用
- `scripts/generate-sitemap.js` - 移動至 scripts 資料夾並更新路徑

### 影響範圍
- [x] 文檔
- [x] 配置
- [ ] 前端功能
- [ ] 後端功能
- [ ] 測試
- [ ] 部署

### 測試說明
1. 檢查所有文檔連結是否正常
2. 驗證 generate-sitemap.js 腳本是否正常運行
3. 確認所有引用路徑已更新

### 相關 Issue/PR
無

### 備註
本次變更主要為文檔整理和結構優化，不影響功能。
```

## 變更記錄最佳實踐

1. **及時記錄**：每次變更後立即記錄
2. **詳細描述**：清楚說明變更內容和原因
3. **分類明確**：使用正確的變更類型標籤
4. **追蹤影響**：標註變更影響的範圍
5. **關聯 Issue**：如有相關 Issue 或 PR，請標註

## 變更類型說明

- **feat**：新功能
- **fix**：錯誤修復
- **docs**：文檔更新
- **style**：代碼格式調整（不影響代碼運行）
- **refactor**：代碼重構（既不是新功能也不是錯誤修復）
- **test**：測試相關（新增或修改測試）
- **chore**：建置過程或輔助工具的變動

---

**注意**：請將變更記錄添加到 `CHANGELOG.md` 的頂部（未發布部分），並在發布版本時整理到對應的版本號下。
